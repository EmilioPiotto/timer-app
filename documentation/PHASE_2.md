## Key Design Decisions

### /api proxy in vite.config.ts
All `fetch('/api/...')` calls from the frontend are proxied to `http://localhost:8000` by Vite during development. This means:
- No CORS issues in dev (same-origin from the browser's perspective)
- `api.ts` uses relative paths (`/api/...`) — unchanged between dev and production (where API Gateway sits at the same domain via CloudFront)

### types.ts mirrors backend exactly
TypeScript types were written to match the Pydantic models 1:1 so that API responses can be typed without transformation:
- `MacroResponse`, `TimerResponse` for GET responses
- `TimerListItem` for the lightweight list (no slot expansion, mirrors `TimerListItem` in backend)
- `ExpandedMacroSlot` for slots returned by `GET /timers/:id` (includes full `macro` object)
- `MacroTemplate` / `TimerTemplate` for template endpoints

### Single api.ts with a shared request() helper
All 14 fetch calls go through one `request<T>()` wrapper that sets `Content-Type`, checks `res.ok`, and parses JSON. Keeps call sites one-liners and error handling consistent.

### TimerEditorPage and MacroBuilderPage serve double duty
`/timers/new` and `/timers/:id` both render `TimerEditorPage`. The component checks whether `:id` is present via `useParams()` to decide between create and edit mode. Same pattern for `MacroBuilderPage`.
